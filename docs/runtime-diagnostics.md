# 运行诊断、日志与社区信息

Alpha 14 的运行数据由已存在的观测器采集，遥测只投影已得到的值。没有为了上报另开第二套高频采样器，也没有重新启用 Minecraft 内存估算。

## 一次游戏启动的数据链

随机 `run` ID 仅关联本次执行，不是稳定用户／设备 ID。

| 事件 | 契约 | 内容 |
|---|---|---|
| `diagnostic.launch` | schema 1 | Java 主版本、classpath/库数量、堆配置、CPU/资源策略与 wrapper 等固定数值／布尔字段 |
| `diagnostic.mods` | schema 2，兼容旧格式 | 分页的模组 ID、版本、依赖、SHA-256、嵌套候选与 provided 别名 |
| `diagnostic.run` | 现有周期窗口 | 可用的 CPU、内存、进程树、GPU 和 I/O 观测，配置 epoch 与序号 |
| `diagnostic.run-summary` | schema 1 | 时长、启动窗口、退出码、峰值／P95 与采集可用性 |

`heap_mib` 是配置，不是堆实测。working set、private bytes、heap、native 和 commit 不互相替代；GPU 本地／共享峰值不能相加伪装成同时发生的峰值。未采集值为 -1，实测零保留为 0。退出码另有 `exit_observed`，因此真实 -1 退出码不会与未知混淆。

模组元数据不证明实际加载器已经选择／激活该模组。解析受字节、深度、数量和时间预算约束；每页最多 4096 字符、最多 129 页，每个模组最多 8 个依赖及 4 个 provided 别名，遗漏会标记不完整。元数据超时仍保留启动配置和不完整的运行上下文。管理页显示缺页和采集缺失，不填造零值。

后台按单次运行提供启动配置、结束汇总、样本和元数据覆盖情况；单次运行记录保留 30 天。日聚合、错误分组的 90 天期限是另一个数据集，不能混用。问卷回复保留 180 天。

## 授权和隐私

必要遥测始终启用；CI/Alpha/Beta 的诊断策略已披露且强制，stable 的诊断默认关闭并可撤回。撤回清除待发诊断并取消含诊断的批次，不撤回服务器已接收数据。详情见[遥测分级](xsr/telemetry-tiers-and-rollouts.md)。

不会上传账户令牌、账户名、个人路径、实例名、存档正文、完整启动参数或原始日志。错误上传仅包含受限的异常类型、符号栈、已知操作和阶段；本地日志保留更详细但经过脱敏的诊断。服务响应耗时与遥测自身上传耗时分别记录，后者受预算限制，避免无限自我上报。

入口为 `https://nexa-telemetry.pcln.workers.dev/v1/events`，不需要 NexaMC 账户、客户端证书或浏览器挑战。失败保留批次并按周期重试，不阻塞游戏。HTTP/TLS 错误应结合阶段和状态码判断，不等价于文件校验损坏。

源码：`RunLifecycleTelemetry.cs`、`RunDiagnosticTelemetry.cs`、`LauncherTelemetrySession.cs`、`CloudflareTelemetryTransport.cs`。后台和管理页位于各自仓库，字段不能只改客户端而不改接收校验。

## 启动器日志与启动失败

每个启动会话使用独立时间戳 `.log` 文件；不是所有会话追加到一个固定文件。文件位于实际配置的日志目录，不能用开发者机器上的固定绝对路径指导所有用户。启动异常写入阶段和异常信息，最多等待三秒刷盘；成功获得文件路径后 Splash 提供日志文件链接。目录不可写或刷盘失败时不会提供伪造链接。

“日志事实导出”与原始会话日志不同：事实导出保留受限诊断信息，不自动包含正文。提交问题时说明版本、系统／架构、触发动作、阶段与异常类型；先检查并删除日志中敏感内容。不要把账户令牌发到工单。

## 公告与问卷

主 UI 启动次数写入本地社区状态；每第 30 次启动邀请填写可关闭的体验问卷，只有主动提交才发送回答。多进程激活不是重复计数的理由。公告是受限纯文本及版本修订，不执行远端 NXML 或 HTML；本地记录已确认修订。后台写入需要既有管理权限和修订校验。

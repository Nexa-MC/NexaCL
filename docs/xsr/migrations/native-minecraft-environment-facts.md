# Native Minecraft environment facts and dependency closure

Java, Minecraft file integrity, installed-loader compatibility and mod inventory
capability providers execute in Minecraft. Foundation retains the hardware broker,
registry definitions and projections. It invokes one asynchronous typed facts port
per provider and reconstructs observations using its own registered definitions.

The wire carrier is a closed scalar union: boolean, 32/64-bit integer, text and text
list, plus availability, confidence, permission, timestamp, source and reason. It
never transports ICapability, reflection metadata, object values or CLR references.
Definition identities and scalar kinds must match the local registry; unavailable
and low-confidence facts retain their original provenance and semantics.

The owner reuses its canonical Java locator, metadata/cache, file verifier and
installation catalog transport. Loader compatibility receives that explicit source
instead of creating a second HTTP owner. Account facts remain with the Accounts
adapter. Pure mod definitions and telemetry syntax validators may move to contracts
with managed forwarding entry points retained. Production UI references contract
projects and native clients; the managed public composition remains available.

Dependency removal is gated by generated protocol checks, representative actual
environment observations, launch/preflight parity, architecture checks, managed
public API compatibility and full production AOT/isolation verification.

Production Foundation now collects the four providers through Native Minecraft.
The actual provider implementations are linked into the owner and excluded from
the native UI build. The local account projection remains in Foundation. Mod
definitions are portable; inventory-reader syntax methods retain their managed
entry points while forwarding to pure contract validators used by telemetry.
Unused platform/telemetry implementation references and production managed-only
router/forwarder roots are removed.

The production UI dependency closure contains no Minecraft or Resources
implementation project. Publishing now enforces that property. Local diagnostic
documents and migration receipt authorization/verification also execute in the
owner; migration adds an asynchronous default verification method while keeping
the managed synchronous compatibility API. Receipts retain the original local
provenance rules and 64 MiB bound, and changed bytes are rejected.

The independent NativeAOT suite observes actual Java, options, manifest and mod
directory data through all five scalar variants, preserves provenance/timestamps,
reads scoped local documents and rejects changed migration receipts. All earlier
installation/library/resource/launch/shutdown cases continue to pass. Generated
schema: 380 shapes, fingerprint
`644D5B14B8856485AF47987705C5244C906BB8DC00B4CA329E49CF34A6407B4C`.
The full production UI AOT, strengthened isolation check, headless shell and real
window-close/exit smoke pass. The managed regression batch passes 106 cases and the
97-project architecture gate passes. No platform or public release signing policy
is changed by this boundary.
